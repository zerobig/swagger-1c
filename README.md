# swagger-1c

Генератор OpenAPI-спецификации для HTTP-сервисов 1С:Предприятие 8.3 и опциональная валидация запросов через библиотеку zod-1c.

Библиотека сканирует метаданные HTTP-сервисов и связанные с ними общие модули `<Имя>Описание`, собирает модель OpenAPI и отдаёт её по HTTP вместе со встроенным UI (Swagger UI, ReDoc, Scalar, Stoplight, RapiDoc).

## Статус

Бета. API библиотеки стабилен, формат модулей `<Имя>Описание` не меняется. Новый генератор OpenAPI 3.1 доступен опционально и не влияет на текущих пользователей.

## Требования

- Платформа 1С:Предприятие 8.3.23 и выше.
- Опционально: расширение `zod-1c` (для рантайм-валидации запросов).
- Опционально: расширение YaxUnit (для запуска тестов библиотеки).

## Установка

### Основное расширение (обязательно)

Установите `swagger-1c.cfe` через Конфигуратор: Конфигурация - Расширения конфигурации - Добавить из файла.

После установки откройте в браузере `/swagger` или `/swagger/swagger.json`. Увидите документацию по всем HTTP-сервисам конфигурации, для которых есть модуль `<Имя>Описание`.

### Библиотека zod-1c (опционально)

`swagger-1c` не требует `zod-1c` для генерации спецификации. Установите `zod-1c`, если хотите использовать `Swag_ZodАдаптер` для валидации входящих запросов по описанию.

## Быстрый старт

Для каждого HTTP-сервиса создайте общий модуль с именем `<Имя>Описание`. В нём должны быть две экспортные функции:

```bsl
Функция ПолучитьОбъектыHTTPСервиса() Экспорт
    // Возвращает массив схем (Swag_Описание.Объект(...).Сформировать())
КонецФункции

Функция ПолучитьОписаниеHTTPСервиса() Экспорт
    // Возвращает массив методов (Swag_Описание.Метод(...).Сформировать())
КонецФункции
```

Методы описываются через fluent-интерфейс:

```bsl
Swag_Описание.Метод("ТоварыGET")
    .ОписаниеМетода("Список товаров")
    .ПараметрЗапроса("page")
        .ТипЗначения("integer")
        .Минимум(1)
    .Ответ(200)
        .ОписаниеОтвета("OK")
        .ТипОтвета("application/json")
            .СхемаОтвета("DemoProduct")
.Сформировать()
```

Имя метода в описании - это `<ИмяШаблонаURL> + <HTTPМетод>`. Например, шаблон URL с именем `Товары` и метод `GET` дают имя `ТоварыGET`.

Пример полностью рабочего сервиса см. в разделе "Демонстрационные сервисы".

## Что входит в библиотеку

### Генераторы спецификации

- Старый генератор (по умолчанию): собирает `swagger.json` в формате OpenAPI 3.0.0 напрямую, без промежуточной модели. Используется с первых версий библиотеки.
- Новый генератор (опционально): собирает модель OpenAPI 3.1 и сериализует её через отдельный слой. Включается настройкой `РежимГенератора`.

### Общие модули

- `Swag_Запросы` - HTTP-методы служебного сервиса `/swagger`, переключение режимов генератора.
- `Swag_Сборщик` - сканирование HTTP-сервисов, сборка модели, диагностика описаний.
- `Swag_Модель` - фабрики и валидатор модели OpenAPI 3.1.
- `Swag_АдаптерСовместимости` - преобразование старого формата описаний в модель OpenAPI 3.1.
- `Swag_СериализаторOpenAPI` - превращение модели в JSON.
- `Swag_ОбработкаHTTP` - вспомогательные функции HTTP (в т.ч. `ОтветJSON`).
- `Swag_ZodАдаптер` - валидация запросов и ответов через zod-1c (требует установленной библиотеки zod-1c).
- `SwaggerОбщиеНастройки` - настройки библиотеки (см. раздел "Настройка").

### Обработки

- `Swag_Схема` - построение JSON Schema (OpenAPI 3.1) через fluent-интерфейс.
- `Swag_Операция` - построение Operation (OpenAPI 3.1) через fluent-интерфейс.

### Служебный HTTP-сервис

`Swag_Сервис` с шаблонами:

- `GET /swagger/{File}` - отдача `swagger.json`, JS, CSS, HTML для UI и JSON-RPC playground.
- `GET /tools/diagnostics` - отчёт о замечаниях в описаниях (параметр `format=json` или `format=csv`).

## Режимы генератора

Настройка `РежимГенератора` в `SwaggerОбщиеНастройки` управляет тем, какой генератор используется для отдачи `swagger.json`.

| Значение | Поведение |
|---|---|
| `"Выкл"` (по умолчанию) | Старый генератор. Поведение не меняется относительно предыдущих версий. |
| `"Мягкий"` | Новый генератор OpenAPI 3.1. Неполные описания (например, пустые `responses`) попадают в журнал регистрации как предупреждения, но JSON отдаётся. |
| `"Строгий"` | Новый генератор OpenAPI 3.1. Любая ошибка в модели приводит к откату на старый генератор и записи в журнал. Подходит для CI. |

По умолчанию используется `"Выкл"`. Если вы не планируете переходить на OpenAPI 3.1, ничего менять не нужно - библиотека работает как раньше.

Пошаговая инструкция по переходу - в [MIGRATION.md](MIGRATION.md).

## Настройка

Все настройки библиотеки - в общем модуле `SwaggerОбщиеНастройки`, функция `ПолучитьОбщиеНастройки()`. Отредактируйте значения в ней, и библиотека подхватит изменения при следующем запросе.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `РежимГенератора` | `"Выкл"` | `"Выкл"` / `"Мягкий"` / `"Строгий"`. См. выше. |
| `Title` | `Метаданные.Имя` | Заголовок API в `info.title`. |
| `Version` | `Метаданные.Версия` | Версия API в `info.version`. |
| `BaseURL` | `""` | Сервер API. Пустая строка - автоопределение из запроса. Явно заданное значение из настроек переопределяет автоопределение. |
| `UseBasicAuth` | `Истина` | Добавлять ли глобальную security-схему `basic`. |
| `МассивНеотображаемыхСервисов` | `[]` | HTTP-сервисы, исключаемые из `swagger.json`. |

Если хотите, чтобы ваши настройки не затирались при обновлении расширения, создайте свой общий модуль `SwaggerОбщиеНастройкиПользователя` с функцией `ПолучитьОбщиеНастройки()` того же формата. Библиотека сначала ищет его, а `SwaggerОбщиеНастройки` использует как fallback.

## Валидация запросов через zod-1c

Если установлено расширение `zod-1c`, для валидации входящих запросов по описанию используется общий модуль `Swag_ZodАдаптер`. В HTTP-методе это одна строка:

```bsl
Функция ТоварыСозданиеPOST(Запрос) Экспорт

    Результат = Swag_ZodАдаптер.ПроверитьЗапрос(
        "Demo_Products", "ТоварыСозданиеPOST", Запрос);

    Если Не Результат.Успех Тогда
        Возврат Swag_ОбработкаHTTP.ОтветJSON(Результат.Ошибки, 422);
    КонецЕсли;

    // Результат.Данные - проверенные и приведённые значения:
    // числа - Числа, uuid - строки, boolean - Булево.
    СоздатьТовар(Результат.Данные);

КонецФункции
```

Поиск операции в модели - по паре `(URL, HTTP-метод)`, восстановленной из метаданных HTTP-сервиса. Поле `operationId` на поиск не влияет и может быть переопределено в описании без последствий.

Для сценариев с высокой нагрузкой предусмотрена функция `ПроверитьЗапросПоМодели(Модель, URL, HTTPМетод, Запрос)`. Модель можно кэшировать в отдельном общем модуле с повторным использованием возвращаемых значений "На время сеанса" или иным способом на уровне вызывающего кода.

### Поведение при отсутствии zod-1c

- Генерация `swagger.json` работает без изменений.
- Обращение к функциям `Swag_ZodАдаптер` вызовет исключение с текстом о необходимости установить `zod-1c`.
- Тестовые модули `swagger-1c`, зависящие от `zod-1c`, не регистрируются в YaxUnit, если `zod-1c` не установлен.

## Диагностика описаний

Для проверки своих описаний перед переходом на новый генератор используется функция `Swag_Сборщик.ДиагностикаОписаний()` или HTTP-метод `GET /tools/diagnostics`.

Отчёт содержит колонки:

| Колонка | Описание |
|---|---|
| `Код` | Идентификатор замечания (например, `OPERATION_RESPONSES_MISSING`). |
| `Путь` | Место в модели (`paths./api/create.post.responses`). |
| `Сообщение` | Что рекомендуется сделать. |
| `Критичность` | `Ошибка` или `Предупреждение`. |
| `Сервис` | Имя HTTP-сервиса, к которому относится замечание. |

Формат ответа:

- `GET /tools/diagnostics` - JSON с полями `total`, `warnings`, `errors`, `items`.
- `GET /tools/diagnostics?format=csv` - CSV для открытия в Excel.

## Демонстрационные сервисы

В расширении есть демонстрационный HTTP-сервис `Demo_Products` с описанием `Demo_ProductsОписание`. Он показывает:

- CRUD-сценарий с четырьмя методами (GET список, GET по id, POST, PUT).
- Валидацию запроса через `Swag_ZodАдаптер`.
- Ранний возврат 422 с детальным списком ошибок.
- Работу с проверенными и приведёнными данными.
- Переиспользование схем `DemoProduct`, `DemoProductInput`, `DemoProductList` через `components.schemas` и `$ref`.
- Описание всех возможных кодов ответов, включая ошибочные.

После установки откройте `/swagger` и найдите группу `Demo_Products`.

## Известные ограничения

1. В общих модулях 1С нет переменных модуля. Модель OpenAPI собирается при каждом запросе к `swagger.json` или при вызове `Swag_ZodАдаптер.ПроверитьЗапрос`. Для оптимизации используйте `ПроверитьЗапросПоМодели` с внешним кэшем.

2. Режим `СовместимостьС30` в `Swag_СериализаторOpenAPI` реализован частично: флаг конвертирует `nullable` и `exclusiveMinimum` в формат OpenAPI 3.0, но не подменяет значение поля `openapi` (остаётся `"3.1.0"`). До полной реализации режим использовать не рекомендуется.

3. `Swag_ZodАдаптер` различает отсутствие ключа в объекте и значение `Неопределено` только при использовании `.ДопускаетNull()` в zod-1c. По умолчанию `.Необязательное()` в zod-1c ведёт себя как `.nullish()` в Zod (TypeScript): пропускает и отсутствие ключа, и `Неопределено`.

4. При использовании YaxUnit и `swagger-1c` одновременно настройте фильтр расширений в YaxUnit, чтобы он не сканировал модули с `ЮТест` в `swagger-1c`.
