## JSON-RPC (OpenRPC)

- Функция `Swag_Сборщик.ДиагностикаОписанийOpenRPC()` — аналог `ДиагностикаОписаний`, но для JSON-RPC сервисов. Возвращает ту же таблицу (`Код`, `URL`, `Сообщение`, `Критичность`, `Сервис`), но с ошибками из `СобратьМодельOpenRPC`.
- HTTP-метод `GET /swagger/diagnostics?protocol=json-rpc` для получения отчёта по JSON-RPC сервисам.
- Поддержка `errors` в OpenRPC-методах через новый модификатор `.ОшибкаJSONRPC(Код, Сообщение)` в `Swag_Описание`. Сейчас клиент ориентируется только на стандартные коды JSON-RPC 2.0.
- Позиционные параметры JSON-RPC (`params` как массив). Сейчас поддерживаются только именованные параметры (`params` как объект).
- Валидатор `Swag_Описание`: запрет смешивания `.ПараметрЗапроса()` с `.ПараметрURL()` / `.ПараметрЗаголовка()` / `.ПараметрФормы()` в JSON-RPC сервисе. Валидатор также может проверять, что у сервиса ровно один шаблон URL (сейчас проверяется в `Swag_Сборщик` при сборке). Внешняя валидация `json-rpc.json` через `openrpc-validator` в CI.
- Тест на ограничение «один шаблон URL»: нужен сервис с двумя шаблонами в тестовой конфигурации.
- Тест на уникальность имён методов между сервисами: нужны два JSON-RPC сервиса с одинаковым именем метода.
- Batch-запросы на нескольких серверах в OpenRPC Viewer: сейчас все запросы отправляются на сервер первого добавленного метода.
- Хранение `Authorization` header для всех методов сервиса в OpenRPC Viewer (сейчас вводится per-method).
- `exampleFromSchema` в OpenRPC Viewer для `$ref`-схем: сейчас возвращает `null`, нужно резолвить ссылку через `components.schemas`.


## Новый генератор и модель

- Полная реализация режима `СовместимостьС30` в `Swag_СериализаторOpenAPI`: подмена `openapi` на `"3.0.3"`, обратное преобразование `type: [..., "null"]` в `nullable: true`, `exclusiveMinimum: N` в `minimum: N, exclusiveMinimum: true`.
- Поддержка `PathItem.parameters` (общие параметры пути).
- Поддержка `webhooks` (OpenAPI 3.1).
- Поддержка `tags` на уровне операции с описаниями.
- Валидатор модели: проверка на циклические `$ref`.
- Расширить API параметров в `Swag_Описание.Параметр*`: методы `.Минимум()`, `.Максимум()`, `.ПоУмолчанию()`, `.ФорматЗначения()`, `.Пример()`. Сейчас они есть только у свойств объектов. Это ограничивает точность описания параметров.

## Интеграция с zod-1c

- Генерация `zod-1c`-схем из спецификации OpenAPI (обратный адаптер, `Swag_ZodГенератор`). Полезно для клиентов, которые получают `swagger.json` из внешней системы.
- Экспорт модели OpenAPI в `zod-1c`-код как текст BSL (для документации и аудита).
- Проверка кэширования модели в общем модуле с повторным использованием возвращаемых значений на время сеанса (готовый рецепт для README).

## Валидация и бизнес-правила

- Кросс-полевые проверки в zod-1c: совпадение полей, диапазон дат, сумма позиций, условная обязательность.
- Автоматическая проверка по ограничениям реквизитов метаданных (`.ПоМетаданным()` в `Zod_Схема` или отдельный метод `Swag_Модель`).
- Дополнительные трансформеры в zod-1c: нормализация email, округление чисел, строка в JSON, JSON в строку.

## Диагностика и CI

- Внешняя валидация `swagger.json` в CI через `openapi-spec-validator` и `@redocly/cli` на эталонном примере.
- Отчёт о миграции в UI (кнопка "Проверить описания" в Swagger UI).
- Более детальная диагностика: предложение конкретной правки в описании для каждого кода ошибки.
