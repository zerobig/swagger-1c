# Миграция на новый генератор OpenAPI 3.1

## Кратко

Если вы не планируете менять генератор, ничего делать не нужно. По умолчанию используется прежний генератор OpenAPI 3.0.0, поведение библиотеки не меняется.

Переход на новый генератор включается одной настройкой. Откат выполняется той же настройкой.

## Что даёт новый генератор

| Аспект | Старый генератор | Новый генератор |
|---|---|---|
| Версия OpenAPI | 3.0.0 с отклонениями от стандарта | 3.1.0, валидный по спецификации |
| `nullable` | `true` рядом с `type` | `type: [..., "null"]` |
| `exclusiveMinimum` | `true` + `minimum: N` | `N` |
| `$ref` с соседними полями | Разрешалось | Только `$ref` |
| Поле `require` в схемах | Присутствовало (опечатка) | Отсутствует |
| Поле `deprecated: null` | Присутствовало | Отсутствует |
| Пустые `responses: {}` | Допускалось | Остаётся, но с предупреждением в журнале |

Для клиентов, которые парсят только содержимое, изменения прозрачны. Для клиентов, которые анализируют поле `openapi`, изменение версии с 3.0.0 на 3.1.0 требует проверки.

## Три режима

| Режим | Поведение |
|---|---|
| `"Выкл"` (по умолчанию) | Старый генератор. Ничего не меняется. |
| `"Мягкий"` | Новый генератор. Неполные описания дают предупреждения в журнале, JSON отдаётся всегда. |
| `"Строгий"` | Новый генератор. Любая ошибка в модели приводит к откату на старый генератор и записи в журнал. |

## Пошаговая миграция

### Шаг 0. Оцените объём работы

Запустите в консоли:

```bsl
Отчёт = Swag_Сборщик.ДиагностикаОписаний();
// или откройте в браузере:
// GET /tools/diagnostics
// GET /tools/diagnostics?format=csv
```

В отчёте перечислены замечания по описаниям:

| Поле | Значение |
|---|---|
| `Код` | Идентификатор замечания |
| `Путь` | Место в модели |
| `Сообщение` | Рекомендация |
| `Критичность` | `Ошибка` или `Предупреждение` |
| `Сервис` | Имя HTTP-сервиса |

Если отчёт пуст, можно сразу включить строгий режим. Если есть только предупреждения, включите мягкий режим. Если есть критические ошибки, сначала доработайте описания.

### Шаг 1. Включите мягкий режим

В общем модуле `SwaggerОбщиеНастройки`:

```bsl
Настройки.Вставить("РежимГенератора", "Мягкий");
```

Перезапустите сеанс. Откройте `swagger.json` в браузере. Он должен открыться и работать в Swagger UI, ReDoc, Scalar, Stoplight, RapiDoc.

Что изменится:
- поле `openapi` примет значение `"3.1.0"`;
- из спецификации уйдут `require`, `deprecated: null`, `$ref` с соседями;
- `nullable` и `exclusiveMinimum` будут в формате OpenAPI 3.1.

Что не изменится:
- состав методов, схем, параметров и ответов;
- клиенты, которые не парсят версию `openapi`, ничего не заметят.

### Шаг 2. Разберитесь с предупреждениями

Откройте журнал регистрации, события `"Swagger: Переход на новый генератор"`. В журнале будут сообщения вида:

```
[OPERATION_RESPONSES_EMPTY_WARN] paths./api/create.post.responses:
responses не заданы. Рекомендуется добавить .Ответ(200).ОписаниеОтвета(...)
```

Для устранения замечания в модуле `<Имя>Описание` найдите метод и добавьте описание хотя бы одного ответа:

```bsl
.Метод("СоздатьPOST")
    .ОписаниеМетода("Создание")
    .Тело()
        .ТипТела("application/json")
            .СхемаТела(Объекты[2].Имя)
    .Ответ(200)
        .ОписаниеОтвета("Успех")
```

Это требование стандарта OpenAPI: даже если метод не возвращает тело, должен быть описан хотя бы один код ответа.

### Шаг 3. Включите строгий режим (опционально)

Когда в журнале нет критичных замечаний:

```bsl
Настройки.Вставить("РежимГенератора", "Строгий");
```

В строгом режиме любая ошибка в модели приводит к откату на старый генератор и записи в журнал. Это защищает от регрессий при последующих изменениях описаний.

### Шаг 4. Откат

```bsl
Настройки.Вставить("РежимГенератора", "Выкл");
```

Никакие другие действия не требуются. Старый генератор продолжает работать без изменений.

## Частые вопросы

### У меня всё работало, зачем переходить

Если `swagger.json` используется только для внутреннего UI, можно не переходить. Переход актуален, если вы:

- отдаёте спецификацию внешним клиентам;
- генерируете по ней SDK для мобильного или веб-фронта;
- хотите, чтобы спецификация проходила аудит на соответствие OpenAPI.

### Что делать с методами без описанных ответов

Добавить `.Ответ(200)` в описание или оставить их в мягком режиме. Мягкий режим не блокирует отдачу JSON.

### Совместимость с инструментами

- Swagger UI - поддерживает OpenAPI 3.1 во всех актуальных версиях.
- Redoc - поддерживает начиная с версии 2.1.
- Scalar, Stoplight, RapiDoc - поддерживают OpenAPI 3.1.
- OpenAPI Generator - поддерживает OpenAPI 3.1.

Если используете инструмент без поддержки OpenAPI 3.1, оставьте `РежимГенератора = "Выкл"`.

### Что если новый генератор упадёт в продакшене

В мягком режиме при исключении в новом генераторе выполняется откат на старый, пользователь получает прежний JSON. В строгом режиме откат выполняется также при невалидной модели. Причина всегда записывается в журнал регистрации.

### Таблица изменений в JSON

| Поле | Было в 3.0.0 | Стало в 3.1.0 |
|---|---|---|
| `openapi` | `"3.0.0"` | `"3.1.0"` |
| `nullable` | `true` рядом с `type` | `type: [..., "null"]` |
| `exclusiveMinimum` | `true` и `minimum: N` | `N` |
| `$ref` с соседями | Допускалось | Только `$ref` |
| `require` | Присутствовало | Отсутствует |
| `deprecated: null` | Присутствовало | Отсутствует |
| `responses: {}` | Допускалось | Остаётся, но с предупреждением в журнале |

## Помощь

Если после миграции возникают проблемы:

1. Запустите `Swag_Сборщик.ДиагностикаОписаний()` и сохраните отчёт.
2. Сохраните выдержку из журнала регистрации по событиям `"Swagger: Переход на новый генератор"`.
3. Создайте issue в репозитории с этими материалами.
