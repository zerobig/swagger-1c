# Как участвовать в разработке

## Сообщения об ошибках

Создайте issue в репозитории. Приложите:

- версию платформы 1С:Предприятие;
- версию расширения `swagger-1c`;
- минимальный пример описания HTTP-сервиса, на котором воспроизводится проблема;
- текст ошибки и выдержку из журнала регистрации.

Если проблема связана с переходом на новый генератор, приложите отчёт `Swag_Сборщик.ДиагностикаОписаний()` в формате CSV.

## Предложения по улучшению

Перед созданием issue с предложением проверьте [BACKLOG.md](BACKLOG.md) - возможно, идея уже зафиксирована. Если нет, создайте issue с описанием сценария использования и предлагаемого поведения.

## Pull request

1. Форкните репозиторий.
2. Создайте ветку от `main`.
3. Внесите изменения. По возможности добавьте тесты в `swagger-1c`.
4. Убедитесь, что все тесты проходят.
5. Создайте pull request с описанием изменений и ссылкой на issue.

Для изменений, затрагивающих API библиотеки или формат модулей `<Имя>Описание`, сначала обсудите предложение в issue.

## Структура репозитория

- `swagger-1c` - основное расширение (код библиотеки, служебный HTTP-сервис, демонстрационные сервисы).
- `MIGRATION.md` - инструкция по переходу на новый генератор.
- `BACKLOG.md` - идеи и задачи на будущее.
- `CHANGELOG.md` - история изменений.

## Стиль кода

- Язык комментариев - русский.
- Публичные функции и процедуры - с комментарием в формате, принятом в 1С (описание параметров и возвращаемого значения).
- Имена методов следуют стилю, принятому в библиотеке. Фабрики схем используют множественное число (`Строки`, `Числа`, `Булевы`, `Даты`, `Массивы`), чтобы не конфликтовать с функциями платформы.
- Методы-модификаторы возвращают `ЭтотОбъект` для поддержки fluent-цепочек.

## Тестирование

Тесты используют YaxUnit. Установите `swagger-1c` и YaxUnit, запустите все тесты через стандартный интерфейс YaxUnit.

Если вы изменяете `Swag_ZodАдаптер` или другой код, зависящий от `zod-1c`, убедитесь, что тесты проходят как с установленным `zod-1c`, так и без него.
